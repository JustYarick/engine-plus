# 🔬 Анализ аналогов и существующих решений

В данном документе проведён детальный технический разбор существующих инструментов для анализа памяти, отладки и реверс-инжиниринга. Мы выделили их сильные стороны, архитектурные решения и недостатки, чтобы взять лучшее в **Engine+**.

---

## 1. Сравнительная таблица аналогов

| Инструмент | Язык / Стек | GUI фреймворк | Платформа | Сильные стороны | Слабые стороны / Проблемы |
|---|---|---|---|---|---|
| **Cheat Engine** | Pascal (Lazarus), C, x86 asm | LCL (Lazarus GUI) | Windows (неофициально Mac) | Золотой стандарт, миллионы таблиц, AutoAssembler, Lua, DBVM гипервизор | Устаревший GUI, Windows-only, монолитная кодовая база, нет нативного AI |
| **PINCE** | Python 3, GDB core | PyQt5 | Linux | Лучший аналог CE на Linux, использует мощь GDB, cheat tables | Медленный (overhead GDB), высокий риск детекта anti-cheat'ами, лаги GUI |
| **scanmem / GameConqueror** | C (core), Python (GUI) | GTK3 | Linux | Легковесный, есть в репозиториях всех дистрибутивов | Примитивный, нет дизассемблера, нет pointer-сканера, устаревший GUI |
| **memflow** | Rust | Нет (headless фреймворк) | Linux, Windows (DMA) | Эталонная Rust-архитектура, DMA (FPGA), модульные PAL traits, скорость | Библиотека, а не GUI-приложение; фокус на DMA/виртуализации |
| **x64dbg** | C++ | Qt 5 | Windows | Архитектура «3-tier Bridge», отличный UI, огромная экосистема плагинов | Windows-only, ориентирован на отладку, а не на сканирование памяти игр |
| **ReClass.NET** | C# (.NET) | WinForms | Windows | Эталонная работа со структурами (node-based reinterpretation), генерация C++ кода | Windows-only, WinForms, нет сканера памяти (нужны готовые адреса) |
| **Ghidra** | Java, C++ (Sleigh) | Java Swing | Мультиплатформа | Автоматический вывод структур (auto-struct), мощнейший decompiler, DWARF/PDB | Статический анализ, нет прямого live-редактирования памяти, тяжёлый Swing |
| **Frida** | C, JavaScript, Python | CLI / API | Мультиплатформа | Динамическая инструментация (hooking на лету), кроссплатформенность | Нет GUI для памяти, требует написания скриптов, порог входа |

## 2. Детальный разбор архитектур и идей для заимствования

### 2.1. Memflow (Rust) — Архитектура доступа к памяти
**Что позаимствовать в Engine+:**
- Использование Rust-трейтов для уровней абстракции:
  - `PhysicalMemory` -> доступ к байтам
  - `VirtualMemory` -> трансляция виртуальных адресов процессов
  - `OsProcess` -> перечисление модулей, памяти, потоков
- Подход к написанию модульных коннекторов (в Engine+ это превращается в Process Access Layer: `ProcMem`, `ProcessVM`, `Ptrace`, `Driver`, `WinAPI`).
- Zero-cost сериализация и безопасность Rust без паник.

### 2.2. ReClass.NET — Модель анализа структур
**Что позаимствовать в Engine+:**
- **Node-Based Memory Representation:** Память отображается как дерево типизированных узлов (Nodes). Пользователь может прямо на лету кликнуть на смещение `+0x18` и сменить тип с `Hex32` на `Pointer -> PlayerEntity`.
- **Автоматическое определение указателей:** Если значение попадает в диапазон валидного региона памяти процесса, узел автоматически подсвечивается как потенциальный указатель.
- **Генерация структур:** Экспорт распознанной раскладки памяти прямо в структуры на C++, Rust или C#.

### 2.3. x64dbg — Паттерн «Bridge»
**Что позаимствовать в Engine+:**
- Полная изоляция движка отладчика/сканера от графического интерфейса:
  ```
  [Core Engine (Rust)] <--- IPC / In-Process Channels ---> [GUI (egui)]
                       <--- JSON-RPC (MCP) -----------> [Любая LLM / Agent]
  ```
- Благодаря этому Engine+ может работать как headless CLI, как GUI приложение или как фоновый MCP-сервер для нейросетей без запуска графики.

### 2.4. Ghidra — Эвристики вывода типов и структур
**Что позаимствовать в Engine+:**
- Изучение инструкций ассемблера, обращающихся к памяти:
  - `mov eax, [rcx + 0x14]` -> поле по смещению `0x14` имеет размер 4 байта (int/float).
  - `movss xmm0, [rcx + 0x18]` -> поле по смещению `0x18` является float (f32).
  - `mov rax, [rcx]` -> смещение `0x00` содержит указатель (вероятно VTable).
- Передача этих паттернов в MCP локальной нейросети, которая мгновенно восстанавливает структуру объекта с именами полей.

### 2.5. PINCE — Опыт Linux-гейминга
**Уроки и ошибки, которые мы исправим:**
- PINCE завязан на медленный парсинг вывода GDB через pipe. Из-за этого сканирование больших объёмов памяти работает медленно, а GUI зависает.
- **В Engine+:** Все сканирования выполняются нативным многопоточным кодом на Rust с прямым чтением через `process_vm_readv` (Linux) / `ReadProcessMemory` (Windows) с параллелизмом Rayon со скоростью в гигабайты в секунду.

## 3. Уникальные преимущества Engine+

1. **AI-Native с MCP:** Ни один существующий аналог не имеет встроенного сервера контекста для нейросетей, позволяющего локальной LLM в реальном времени анализировать память и реверсить код.
2. **Современный Rust-стек:** Полная безопасность памяти, отсутствие утечек, скорость C++, легковесный запуск.
3. **Кроссплатформенный PAL:** Одинаково эффективная работа на Linux, Windows и Wine/Proton.
4. **Гибридный скрытный доступ (Stealth):** От юзермодных прямых сисколлов до LKM-драйвера.
5. **Безопасная скриптовая система:** Легковесный Lua 5.4 со строгой песочницей (`sandbox=true`), гарантирующей безопасность скачиваемых чит-таблиц.
