## 1. 🖥️ UI Framework

**Вопрос:** Какой UI framework использовать?

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **egui** (рекомендую) | Чистый Rust, быстрый dev cycle, immediate mode | Менее "нативный" вид |
| **iced** | Elm-архитектура, красивее | Менее гибкий layout, медленнее dev |
| **Tauri + React/Svelte** | Максимально красивый UI, привычный web-стек | Overhead, сложнее интеграция с Rust |
| **Slint** | Декларативный UI, preview | Лицензия (GPL для open-source) |

> **Моя рекомендация:** Начать с **egui + egui-dock** для быстрого прототипа.
> Если нужен "production-quality" UI — переходить на Tauri позже.

## 2. 🎯 Целевая платформа — [РЕШЕНО ✅]

**Решение:** 
1. **Linux (Первичная целевая ОС):** Нативная поддержка, запуск через `sudo` (полный доступ к `/proc/pid/mem`, `process_vm_readv`, ptrace и загрузке LKM).
2. **Windows 10/11:** Нативная поддержка (x64 и WOW64 32-bit), запуск от имени Администратора (автоматическое получение `SeDebugPrivilege`).
3. **Wine / Proton (Steam Deck):** Полная поддержка анализа Windows-игр на Linux через Proton.
4. **macOS:** Исключён из скоупа проекта.

---

## 3. 📝 Scripting Engine — [РЕШЕНО ✅]

**Решение:** Выбран **Lua 5.4** через `mlua` с фичей `vendored` (статическая линковка).
**Python исключён из ядра** по следующим причинам:
1. **Безопасность чит-таблиц:** Пользователи скачивают чужие таблицы. Lua изолируется в песочнице (`sandbox=true`) на 100%, блокируя доступ к файлам и сети. В Python сделать надёжный sandbox невозможно.
2. **Нулевые зависимости:** Lua компилируется прямо в бинарник (+350 КБ). Не требуется установка Python или системных DLL.
3. **Скорость и отсутствие GIL:** Микросекундный старт и возможность запускать скрипты параллельно.
4. **Совместимость:** Комьюнити Cheat Engine уже привыкло к синтаксису Lua.

## 8. 🎨 Стиль дизассемблера

**Вопрос:** Какой синтаксис по умолчанию?

| Синтаксис | Пример | Кто использует |
|-----------|--------|---------------|
| **Intel** | `mov eax, [rbx+0x10]` | IDA, CE, x64dbg, большинство |

## 9. 🔧 Kernel driver: C или Rust?

**Вопрос:** На чём писать kernel module?

| Вариант | Описание |
|---------|----------|
| **C** (рекомендую) | Стандартный подход, вся документация на C |
| **Rust** (experimental) | Rust-for-Linux, но нестабильно и сложнее |
| **C core + Rust wrapper** | C для kernel, Rust для userspace wrapper |

> **Рекомендация:** C для kernel module + Rust FFI wrapper для userspace.
> Rust-for-Linux ещё слишком нестабилен для production.
